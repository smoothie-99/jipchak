# 성공확률 모델 승격과 복구

이 기능은 자동 재학습되는 16차원 성공확률 MLP에 적용됩니다. YOLO 탐지 모델의 성능 검증은 별도입니다.

## 수집과 학습 데이터

- `START`마다 고유한 `attempt_id`를 발급합니다. 같은 `session_id`를 재사용해도 이전 판의 늦은 추론은 새 판에 연결하지 않습니다.
- Arduino의 기존 `GRAB_START` 이벤트에서 마지막으로 완료된 유효 관측을 확정합니다. 기본 2초보다 오래된 관측, 관측이 없는 판, 이벤트가 없는 판은 학습하지 않습니다.
- Depth 누락·크기 불일치·유효 픽셀 부족은 `unknown`입니다. 정상적인 실패의 confidence가 낮다는 이유로 제외하지 않습니다.
- JSONL의 형식 오류·비정상 라벨·NaN/Inf·중복 attempt는 통계와 학습에서 공통으로 제외합니다.
- 신규 수집 기록은 `schema_version=2`, `dataset_role=train|promotion`으로 구분합니다. session ID의 SHA-256 해시로 약 20%의 세션을 승격 평가용으로 예약하며, 같은 세션의 모든 판은 같은 용도를 유지합니다.
- 기존 기록은 학습용입니다. 기존 모델이 사용한 데이터를 새 hold-out으로 재분류하지 않습니다. 과거 기록에 센서 장애가 실제 실패처럼 기록됐다면 원본 영상으로 확인해 정리해야 합니다.
- 평가 기록은 학습, 정규화 통계, Early Stopping, 확률 보정에서 모두 제외합니다. 학습과 평가에 같은 세션이 섞인 파일에서는 해당 세션의 평가 행을 사용하지 않습니다.

WebSocket `GAME_RESULT`에 `outcome_status`와 `outcome_reason`을 추가했습니다. 기존 Spring API의
`isSuccess` Boolean 전송 형식은 호환성을 위해 유지합니다. 따라서 `unknown`을 DB와 관리자
화면에서도 별도로 표시하려면 후속 API/화면 변경이 필요합니다. `unknown` 기록은 이 학습 파이프라인에 들어가지 않습니다.

## Model Promotion

1. 수집 데이터 스냅샷을 만들고 학습 전용 기록으로 후보를 학습합니다.
2. 독립된 확률 보정 데이터가 100건 미만이면 보정을 생략합니다. 100~999건은 sigmoid, 1,000건 이상은 isotonic을 사용합니다. 두 클래스 모두 보정 데이터에 5건 이상 필요합니다. 보정 데이터와 epoch 선택용 validation은 서로 분리합니다.
3. 운영 상태를 변경하지 않고 후보 체크포인트의 차원, 가중치, 정규화, 보정 값, 실제 예측 출력을 검사합니다.
4. 동일한 평가 행을 기존 모델과 후보에 입력합니다. 각 모델의 자체 정규화 및 보정을 적용합니다. 기존 ML 모델이 없는 최초 승격은 평가 기록에 저장된 규칙 기반 예측과 비교합니다.
5. 아래 기준을 전부 통과한 후보만 설치합니다. 기준 미달·표본 부족·예외가 발생하면 운영 모델을 유지합니다.

초기 기본값은 실제 장비에서 조정하기 위한 출발점이며, 현장 검증된 기준값을 의미하지 않습니다.

| 환경변수 | 기본값 | 의미 |
|---|---:|---|
| `SUCCESS_HOLDOUT_RATIO` | 0.2 | 새 세션 중 평가용 예약 비율 |
| `SUCCESS_MAX_OBSERVATION_AGE` | 2.0 | 파지 직전 관측의 최대 나이(초) |
| `SUCCESS_PROMOTION_MIN_SAMPLES` | 30 | 최소 평가 기록 수 |
| `SUCCESS_PROMOTION_MIN_CLASS_SAMPLES` | 5 | 평가용 성공·실패 각각의 최소 수 |
| `SUCCESS_PROMOTION_MIN_BRIER_IMPROVEMENT` | 0.005 | 기존 대비 최소 Brier Score 개선 폭 |
| `SUCCESS_PROMOTION_MAX_LOG_LOSS_REGRESSION` | 0.02 | 허용 Log Loss 악화 폭 |
| `SUCCESS_PROMOTION_MIN_SLICE_SAMPLES` | 10 | 인형 종류별 비교에 필요한 최소 기록 수 |
| `SUCCESS_PROMOTION_MAX_SLICE_BRIER_REGRESSION` | 0.02 | 인형별 허용 Brier Score 악화 폭 |

불확실성은 세션 단위 bootstrap 500회로 확인하며, 최소 5개 평가 세션과 Brier 개선의
95% 구간 하한이 0보다 클 것을 요구합니다. 표본이 적은 인형 그룹은 평가를 생략하며,
승격 결과가 해당 그룹의 성능을 보장하지 않습니다. ECE와 구간별 예측/실제 성공률도 기록합니다.

기존의 30건/각 클래스 5건/신규 10건 조건은 재학습 조건입니다. 모델 적용에는 충분한
학습 전용 데이터와 평가 데이터가 모두 필요하므로, 수집 30건만으로 자동 적용되지는 않습니다.
거절·실패한 후보도 처리한 데이터 수를 기록해 같은 데이터로 학습을 계속 반복하지 않습니다.

평가셋을 반복 사용하면 선택이 그 평가셋에 맞춰질 수 있습니다. 운영 전 별도의 새 수집
기간에서 재검증하고, 환경이 바뀌면 평가셋 버전을 관리하세요. 자동 Depth 라벨의 정확성은
실제 배출 여부/영상 확인으로 검증해야 하며, 센서가 만든 라벨만으로 실장비 정확도를 주장하면 안 됩니다.

## 버전과 복구

`SUCCESS_MODEL_PATH=/data/learning/success_evaluator.pth`일 때 다음 파일을 사용합니다.

- `success_evaluator_versions/<버전>.pth`: 학습된 후보 버전(거절 후보 포함)
- `success_evaluator.pth`: 활성 모델
- `success_evaluator.pth.previous`: 이전 정상 모델
- `success_evaluator.pth.promotions.jsonl`: 데이터 해시·기준·지표·승격/거절 이유·처리 기록 수

설치 전 검증 후, 이전 파일을 영속 백업하고 새 파일을 원자적으로 교체합니다.
메모리 활성화 실패 시 파일과 메모리를 이전 상태로 되돌립니다. 재시작 시 활성 파일이
없거나 손상됐다면 이전 정상 파일을 검증해 복구합니다. 둘 다 사용할 수 없으면 규칙 기반으로 동작합니다.

수동 롤백은 **AI 서버를 중지한 상태에서**, `ai/` 폴더에서 실행합니다.

```bash
python -m src.learning.model_store --model /data/learning/success_evaluator.pth
# 명령이 성공한 뒤 AI 서버를 재시작합니다.
```

`GET /health`의 `success_learning`에서 학습/평가 기록 수, 활성 모델 버전,
마지막 승격 판단, 시작 시 복구 출처를 확인할 수 있습니다. 파일과 버전 디렉토리는 같은
영속 볼륨에 보관하세요. 이 수집기는 장비 1대·단일 AI 프로세스를 전제로 합니다.
여러 worker/서버가 같은 파일에 쓰는 운영은 별도 데이터 저장소와 학습 작업 잠금이 필요합니다.
버전 파일과 판단 기록은 자동 삭제하지 않습니다. 실제 운영 전 보관 정책과 디스크 용량을 정하세요.
