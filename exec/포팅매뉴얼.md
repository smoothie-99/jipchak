```env
# --- 서비스 포트 매핑 (호스트 측) ---

AI_PORT=8001                        # (현재 미사용, RunPod 분리)

# --- Jenkins ---

# --- Nginx ---
NGINX_HTTP_PORT=80
NGINX_HTTPS_PORT=443

# --- 영상 저장 (Spring Boot 가 영상 mp4 저장 → QR 다운로드용) ---

# --- Spring Boot 멀티파트 업로드 한도 ---
SPRING_SERVLET_MULTIPART_MAX_FILE_SIZE=100MB
SPRING_SERVLET_MULTIPART_MAX_REQUEST_SIZE=100MB

# --- Frontend 빌드 타임 변수 (Vite import.meta.env.*) ---

```


빌드되는 컨테이너:

### 3-5. RunPod — AI 서버 가동

RunPod 대시보드에서 GPU Pod 생성 (`runpod/pytorch:2.4.1-py3.10-cuda12.1.1-devel-ubuntu22.04` 권장).

Pod 콘솔(SSH 또는 Web Terminal):
```bash
cd /workspace
git clone <GitLab URL> jipchak
cd jipchak/ai
cp .env.example .env
vim .env             # 위 2-3 항목 참조

pip install -r requirements.txt
nohup python -m uvicorn main:app --host 0.0.0.0 --port 8000 \
  > /tmp/ai.log 2>&1 &
sleep 5
curl http://localhost:8000/health
```

발급된 RunPod proxy URL(`https://<pod-id>-8000.proxy.runpod.net`)을
`infra/.env` 의 `VITE_WS_STREAM_PATH` 에 반영 → 프론트엔드 재빌드.

### 3-6. Raspberry Pi — 키오스크 + 카메라 송신

```bash
# 시스템 의존성
sudo apt-get install -y python3-pip git chromium-browser

# librealsense2 (D435 SDK) 빌드 — Raspberry Pi 공식 가이드 참조
# → 빌드 산출물 중 pyrealsense2 를 Python venv 에 복사

# 코드 클론 및 의존성
git clone <GitLab URL> ~/jipchak
cd ~/jipchak/embedded/raspberrypi/legacy
pip install opencv-python-headless msgpack websockets numpy lz4 pyserial

# /dev/arduino_jipchak 심볼릭 링크 설정
```

키오스크 모드 Chromium 자동 실행은 `~/.config/lxsession/LXDE-pi/autostart` 또는 systemd 서비스로 등록.

## 4. 배포 시 특이사항

### 4-1. WebSocket 라우팅 (중요)

- 실시간 카메라 스트림 (`/ws/stream`, `/ws/camera`)은 **EC2 Nginx 를 거치지 않고 RunPod proxy 로 직접 연결**됨.
- `infra/nginx/conf.d/default.conf` 의 `/ws/` location 은 의도적으로 주석 처리되어 있음 (AI 컨테이너가 EC2 에 없어 nginx upstream resolve 실패 → crash loop 방지).
- 프론트엔드 빌드 시 `VITE_WS_STREAM_PATH` 가 RunPod 절대 URL 로 주입되어야 동작.

### 4-2. RunPod URL 가변성

RunPod pod 재시작 시 proxy URL이 바뀔 수 있음.
변경 시 다음 위치 모두 갱신 후 재빌드 필요:
- `infra/.env` 의 `VITE_WS_STREAM_PATH`
- RPi `rpi_full.py` 실행 인자 `--url`
- 프론트엔드 docker rebuild (`docker compose up -d --build frontend-jipchak`)

### 4-3. CORS 도메인

운영 도메인이 바뀌면 `application.yml` 의 `jipchak.cors.allowed-origins` 또는
환경변수 `JIPCHAK_CORS_ALLOWED_ORIGINS` 갱신 필요.

### 4-4. 영상 저장 디렉토리 권한

- `HOST_VIDEO_DIR` 호스트 경로는 컨테이너 user(uid 1000)이 쓰기 가능해야 함.
- `chown -R 1000:1000 ./videos` 권장.

### 4-5. TLS 인증서

- Let's Encrypt 인증서는 호스트의 `/etc/letsencrypt` 를 nginx 컨테이너에 read-only 마운트.
- 90일마다 갱신 필요 (`sudo certbot renew && docker compose restart nginx`).

### 4-6. Vite 빌드 타임 환경변수

- `VITE_*` 변수는 **빌드 시점에 번들에 정적 삽입**됨.
- 운영 중 값을 바꾸면 반드시 `frontend-jipchak` 컨테이너 재빌드(`--build`) 필요.
- 단순 `restart` 만으로는 반영 안 됨.

### 4-7. Jenkins CI/CD

- GitHub Webhook 으로 `dev` 브랜치 push 시 자동 트리거.
- Frontend / Backend 변경 감지 후 docker build & deploy.
- AI 서버는 현재 자동 배포 대상 아님 → RunPod 수동 `git pull` 필요.
- 빌드 실패 시 자동 배포 중단 (`Frontend CI` stage 의 typecheck + vitest 통과 필수).

### 4-8. 멀티 클라이언트 부하

- `relay_hub.py` 의 `relay_interval` 로 브라우저 스트림 fps 제한 (현재 10fps cap).
- 3대 이상 동시 접속 시 RunPod CPU 부하 누적 가능 → fps 추가 조정 필요.

### 4-9. JPA `ddl-auto` 운영 경고

- 현재 default `update`. 운영 안정화 후 `validate` 또는 `none` 로 변경 권장 (의도치 않은 스키마 변경 방지).

### 5-5. DB 스키마

데이터베이스명: **`jipchak_db`** (utf8mb4 / utf8mb4_unicode_ci)

주요 테이블 (JPA 자동 생성, 운영 시 `ddl-auto=validate` 권장):
- 게임 로그 (game_log)
- 세션 / QR 정보 (Redis)
- 기타 (관리자 통계용)

스키마 초기화는 `exec/dump.sql` 사용.
